# Multi-provider dispatch evaluation

How the coordinator uses the planner, collector, history and evaluation during normal orchestration (#113, parent #103), plus a representative live evaluation against the `docs/agents/models.md` baseline. This document never launches workers and must not be regenerated by starting duplicate ones.

## Coordinator workflow

1. **Collector** — `scripts/orca-usage.mjs` (systemd user service when installed) polls Claude, Codex, Cursor and Antigravity every minute into a local SQLite history. Inspect with `node scripts/orca-usage.mjs status` / `readings`. Do not install the service from a worktree; tests use `--state-dir` / `ORCA_USAGE_STATE_DIR`.
2. **Plan** — `node scripts/orca-plan.mjs --wave <file.json>` refreshes all four readers before balancing a ready wave (capability first, then scarcity, shared load, concurrency). Single-task: `node scripts/orca-recommend.mjs`. Neither command starts a worker.
3. **Decide** — Accept, pick an alternative, or override; write the choice into the worker spec. Jev confidence is an assessment signal, not proof that the assignment is correct.
4. **Launch** — Existing preflight / `orca-spawn.sh` / receipt checks only. Keep concurrency modest.
5. **History & learning** — After finish, `node scripts/orca-history.mjs` stores outcomes; `node scripts/orca-learn.mjs` inspects adjustments. Learning may reorder within a tier but keeps `baselineRecommendation` visible.
6. **Evaluate** — Controlled reports: `node scripts/orca-dispatch-eval.mjs --scenarios <file.json>`. Live verification is this document. Re-run readers and the planner with judgment; do not re-dispatch workers to refresh the evaluation.

### Collection limitations (live)

- **Cursor agent-scope:** reader `limited` (API model bucket exhausted) maps to collector `unknown` so a partial reading is never treated as confirmed capacity for every Cursor model. Model-specific `candidateAvailability` remains available on the reader.
- **Antigravity:** group windows are provider-specific; Argon weekly near exhaustion yields collector `low` while other families still have headroom.
- **Claude:** undocumented OAuth usage endpoint (`source.official: false`); scoped weekly windows can be `limited` without exhausting shared session/week.
- **Installed systemd collector:** not installed on this machine for this task (worktree must not install it). Minute polling and backoff are covered by unit tests with a fake clock; live refresh used a temporary `ORCA_USAGE_STATE_DIR` only.
- **Remote hosts:** non-local `--host` remains `unknown_account` / `host_not_local` without reading local credentials (unchanged).

## Repeatable controlled evaluation

```sh
node scripts/orca-dispatch-eval.mjs --scenarios path/to/scenarios.json
node scripts/orca-dispatch-eval.mjs --scenarios path/to/scenarios.json --json
```

Unit coverage: `tests/orca-dispatch-eval.test.mjs` (`buildDispatchEvaluation summarizes controlled hard, constrained, shared, override and learning cases`, CLI markdown/json). Live data must not be substituted into those fixtures as a pass.

## What this does not claim

- Jev confidence does not prove an assignment is correct.
- A mock-backed reader test is not live integration evidence.
- Collector `fresh` / `low` is a snapshot, not a reservation.
- Disagreement with the models.md baseline is reported, not automatically treated as a planner defect.
